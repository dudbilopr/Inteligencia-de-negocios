Fundamentos Teóricos de DAX

Módulo Conceptual

Antes de modelar, es imperativo dominar el motor analítico de Power BI: Data Analysis Expressions (DAX). A diferencia del código secuencial, DAX es un lenguaje funcional y dinámico diseñado para manejar bases de datos relacionales a través de contextos de filtro.

1. Tablas Calculadas

Almacenan datos en RAM (aumentan el tamaño del modelo). Son vitales para Tablas de Fechas exclusivas, Dimensiones de Rol (ej. Fecha Envío vs Fecha Orden para evitar relaciones inactivas ambivalentes) y simulaciones de Análisis de Hipótesis (What-If).

2. Columnas Calculadas

Se evalúan fila por fila en tiempo de actualización (Refresh). Utilizan RAM estática. Úsalas únicamente para categorizar o segmentar ejes, no para agregaciones numéricas, ya que degradan el rendimiento computacional.

3. Medidas (Explícitas)

Se calculan en tiempo de consulta (on-the-fly) utilizando la CPU. Resumen métricas bajo un contexto dinámico (filtros de usuario). A diferencia de las medidas implícitas (símbolo $\Sigma$), las explícitas aseguran gobierno y reutilización.

Sintaxis, Buenas Prácticas y Variables (VAR)

  • Nomenclatura Estricta: Los nombres de tablas con espacios deben ir entre comillas simples ('Sales Territory'). Las columnas siempre en corchetes e idealmente precedidas por su tabla ('Sales'[Unit Price]). Las medidas solo llevan corchetes ([Total Ventas]), jamás el nombre de la tabla, pues son agnósticas.
  • Indentación y Espacios: DAX ignora los espacios en blanco. Usa Shift + Enter y tabulaciones para jerarquizar el código. El formato es obligatorio para el mantenimiento corporativo.
  • Rendimiento con Variables: En cálculos anidados, usa VAR y RETURN. Las variables almacenan resultados temporales evaluándolos una sola vez, acelerando drásticamente la consulta en vez de recalcular iteraciones (como sucede al usar EARLIER o múltiples CALCULATE redundantes).

Tipado de Datos, BLANK y Operadores Estratégicos

DAX posee inferencia implícita de tipos (Entero, Decimal Real 64-bits, Booleano, Cadena). Sin embargo, la gestión de la "ausencia de valor" (BLANK) es una trampa común de arquitectura.

Concepto CríticoImplementación en DAX
Igualdad vs IdentidadEl operador = asume que BLANK y Cero (0) son iguales. Para seguridad financiera, si buscas un cero estricto, debes usar el operador estricto ==.
Gestión de DivisiónJamás uses el operador / si el denominador proviene de un cálculo volátil. Usa la función DIVIDE(Numerador, Denominador, [Alternativa]), la cual previene los costosos errores de "División por Cero" interceptando los BLANK a nivel de motor.
Recuento de EntidadesPara KPIs como "Base de Clientes Activos", no uses COUNT. Debes aislar los duplicados usando DISTINCTCOUNT.
Operadores Lógicos (IN)Para múltiples filtros OR (ej. País es Chile, Perú o Colombia), evita anidar ||. Usa Columna IN {"Chile", "Perú", "Colombia"} para consultas limpias y rápidas.

Implementación de Medidas (DAX)

Aplicando los conceptos del módulo teórico, crea una tabla contenedora _Medidas e implementa los siguientes scripts respetando la indentación.

A. Agregaciones Base (Uso Seguro de DIVIDE y DISTINCTCOUNT)

Total Ventas = SUM('Sales'[Sales Amount]) Total Costo = SUM('Sales'[Total Product Cost]) Margen Bruto = [Total Ventas] - [Total Costo] // Prevención implícita contra la división por cero % Margen = DIVIDE([Margen Bruto], [Total Ventas], 0) // Recuento único, filtrando clientes repetidos Total Clientes Activos = DISTINCTCOUNT('Sales'[CustomerKey])

B. Filtrado Avanzado (CALCULATE & Operadores IN)

Usamos CALCULATE para sobrescribir el contexto de filtro nativo del visual.

Ventas Internet = CALCULATE( [Total Ventas], 'Sales Order'[Channel] = "Internet" ) // Uso del operador de conjunto IN para agrupar geografías Ventas Pacífico = CALCULATE( [Total Ventas], 'Sales Territory'[Group] IN {"Pacific", "Australia"} )

C. Rendimiento Extremo: Inteligencia de Tiempo usando Variables (VAR)

Para calcular el crecimiento interanual (YoY), almacenaremos las métricas temporales en RAM (Variables) para no recalcular la fórmula múltipes veces.

Crecimiento YoY % = VAR IngresosAñoAnterior = CALCULATE( [Total Ventas], SAMEPERIODLASTYEAR('Date'[Date]) ) RETURN DIVIDE( [Total Ventas] - IngresosAñoAnterior, IngresosAñoAnterior )

Gobernanza de Datos (Row-Level Security)

Por lineamientos corporativos, debemos blindar el modelo. En lugar de crear un reporte aislado para cada país, unificaremos la gobernanza en el modelo subyacente.

Nivel 1: RLS Estático

Se inyectan condiciones DAX fijas.

  1. Modelado > Administrar roles.
  2. Crea el rol Directiva_Europa.
  3. Filtra la tabla Sales Territory con DAX estricto:
    [Group] == "Europe"
  4. Prueba desde la opción "Ver como...", simulando la vista directiva.

Nivel 2: RLS Dinámico

Escalabilidad global usando credenciales UPN de Microsoft 365.

  1. Crea una tabla en Power BI UserSecurity con las columnas Email y TerritoryGroup. Agrega tu correo real.
  2. Relaciona UserSecurity[TerritoryGroup] y Sales Territory[Group]. Crítico: Flujo de filtro Bidireccional y aplica seguridad cruzada.
  3. Crea el rol Seguridad_Dinamica aplicando en la tabla de usuarios:
    [Email] = USERPRINCIPALNAME()
