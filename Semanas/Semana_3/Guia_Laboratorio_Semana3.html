Pipeline Paso a Paso (Transformación)

Paso 1: Normalización de Textos

Dificultad: Básica

Objetivo: Limpiar `Ciudad_Origen` y `Cliente_Nombre` eliminando espacios fantasma (Trim) y aplicando mayúscula inicial (Proper).

Adicionalmente, realiza los siguientes reemplazos de valores (Reemplazar los valores erróneos por los correctos):

  • 'BGA' ➔ 'Bucaramanga'
  • 'Barranqilla' ➔ 'Barranquilla'
  • 'Bogo-ta' ➔ 'Bogotá'
  • 'Bio-Health' ➔ 'Bio Health'
  • 'N3o Systems' ➔ 'Neo Systems'
= Table.TransformColumns(PasoAnterior, {{"Ciudad_Origen", Text.Trim, type text}, {"Ciudad_Origen", Text.Proper, type text}})

Paso 2: Saneamiento Numérico y Monedas

Dificultad: Intermedia

Objetivo 1: Reemplazar comas (,) por puntos (.) en 190 filas de `Precio_Unitario_USD` y convertir el tipo de dato a Moneda (Currency.Type).

Objetivo 2: Corregir 99 cantidades negativas en `Unidades_Vendidas` aplicando el valor absoluto.

= Table.TransformColumns(PasoAnterior, {{"Unidades_Vendidas", Number.Abs, type number}})

Paso 3: Depuración de Incompletos y Nulos

Dificultad: Intermedia

Objetivo 1: Tratamiento de 89 filas que contienen el texto literal "N/A" en `Descuento_Aplicado`. Debes reemplazarlos por el valor especial null y luego tipar la columna como Porcentaje.

Objetivo 2: Depurar (eliminar) 82 registros que tengan valores nulos o vacíos en la columna crítica `Fecha_Venta`.

Construcción del Modelo en Estrella (Star Schema)

Duplicar vs Referenciar

Duplicar: Copia todo el script M y lo vuelve a ejecutar desde cero de forma aislada. Útil para crear dimensiones independientes que apliquen plegado (Query Folding) directo al servidor.

Referenciar: Apunta al resultado final de una consulta previa. Útil si la limpieza original fue muy pesada localmente y quieres reciclarla sin reprocesar todo desde el origen.

Instrucciones de Modelado

  1. Dim_Clientes: Duplica la consulta limpia. Elimina todas las columnas excepto Cliente_Nombre. Elimina duplicados (Table.Distinct). Agrega una Columna de Índice desde 1 (Llamada Cliente_ID).
  2. Dim_Geografia: Duplica la consulta limpia. Mantén Ciudad_Origen. Elimina duplicados. Agrega un Índice (Ciudad_ID).
  3. Fact_Ventas: En tu tabla principal, haz un Merge (Combinar Consultas) con las dos dimensiones recién creadas para traer Cliente_ID y Ciudad_ID. Luego elimina las columnas de texto originales.

erDiagram Dim_Clientes ||--o{ Fact_Ventas : "1-a-Muchos" Dim_Geografia ||--o{ Fact_Ventas : "1-a-Muchos" Dim_Clientes { int Cliente_ID PK string Cliente_Nombre } Dim_Geografia { int Ciudad_ID PK string Ciudad_Origen } Fact_Ventas { string Transaction_ID PK int Cliente_ID FK int Ciudad_ID FK date Fecha_Venta int Unidades_Vendidas }

Tip Arquitectónico:

Las relaciones 1:N con filtro de dirección única garantizan que la propagación del contexto de filtro en DAX sea eficiente y sin ambigüedades. ¡Nunca uses relaciones N:N directamente!
