Almacenamiento Columnar vs. Fila: VertiPaq

Compresión de Diccionarios

Power BI almacena la información por columnas en lugar de filas. Si tienes 1 millón de filas pero solo 3 países distintos, el motor solo guarda 3 valores únicos en memoria RAM y los indexa.

Regla de Oro:

"Elimina las columnas innecesarias antes de preocuparte por la cantidad de filas."

Query Folding: Delegando la Carga al Servidor Origen

Es la capacidad de traducir gráficamente tus pasos de Power Query en una consulta SQL nativa que se ejecuta en el servidor origen (ej. SQL Server) y no en tu memoria RAM local.

Paso 1: Filtro Soportado (SQL)

Filtramos por "Año 2026". El plegado está ACTIVO. El servidor SQL hace el trabajo.

Paso 2: Transformación No Soportada

Ejecutamos un script de Python. El plegado se ROMPE aquí permanentemente.

Paso 3: Cuello de Botella Local

Todo el millón de filas se descarga en crudo a la RAM de tu laptop para procesarse localmente.

Tip de Performance: Filtra, agrupa y elimina columnas al INICIO de tu script M.

Anatomía Estructurada del Lenguaje M

Paradigma Funcional

Cada paso es una variable inmutable que referencia a la variable del paso inmediatamente anterior.

Case-Sensitive

M diferencia entre mayúsculas y minúsculas de manera estricta. Table no es lo mismo que table.

Bloque let ... in

let define las variables y pasos lógicos. in define qué variable (paso) se devolverá finalmente como resultado de la consulta.

let
    Origen = Csv.Document(File.Contents("Datos.csv"),[Delimiter=";"]),
    
    Encabezados = Table.PromoteHeaders(Origen, [PromoteAllScalars=true]),
    
    TiposCambiados = Table.TransformColumnTypes(
        Encabezados,
        {{"Unidades", Int64.Type}, {"Precio", type number}}
    ),
    
    LimpiarTexto = Table.TransformColumns(
        TiposCambiados,
        {{"Ciudad", Text.Trim, type text}}
    )
in
    LimpiarTexto

El Corazón de DAX: Contextos de Evaluación

Contexto de Fila

Row Context (La Capacidad de Iterar)

Es la conciencia que tiene DAX de la fila actual en una tabla durante una iteración celda a celda.

  • Se crea automáticamente al agregar Columnas Calculadas.
  • Se invoca manualmente al usar funciones que terminan en X (SUMX, FILTER).
  • NO filtra datos automáticamente por relaciones.

Contexto de Filtro

Filter Context (El Entorno Visual)

Es el conjunto de filtros aplicados externamente a los datos antes de realizar el cálculo analítico.

  • Se genera mediante Ejes, Slicers, cruces (clics) en gráficos o la función CALCULATE.
  • Aplica obligatoriamente sobre todas las Medidas (Measures).
  • Se propaga a través de las relaciones del modelo.

Agregadores (SUM) vs. Iteradores (SUMX)

Error (Agregador)

Ventas_Err = SUM(Tabla[Cant] * Tabla[Precio])

SUM no tiene contexto de fila, no puede iterar para multiplicar.

Solución (Iterador)

Ventas_Ok = SUMX(Tabla, Tabla[Cant] * Tabla[Precio])

SUMX crea un contexto de fila en memoria RAM.

CALCULATE & Transición de Contexto

1. Sobrescribir Filtros

CALCULATE es la única función capaz de alterar el contexto de filtro externo provisto por un usuario (Slicers/Visuales).

CALCULATE(
  [Total_Ventas],
  Dim_Geografia[Ciudad] = "Bogotá"
)

2. Transición de Contexto

Al invocar una [Medida] dentro de un contexto de fila, DAX automáticamente envuelve la medida en un CALCULATE() invisible.
