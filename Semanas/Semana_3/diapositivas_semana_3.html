Desmitificando Power Query

¿Qué es y dónde se instala?

Power Query NO es un programa separado que debas descargar o instalar. Es un motor de transformación de datos (ETL) que ya viene integrado de forma nativa en las herramientas analíticas de Microsoft.

En Microsoft Excel

A partir de Excel 2016, viene preinstalado. Se encuentra en la pestaña Datos > Obtener Datos. Todo lo que aprendas de M aquí, funciona exactamente igual en Excel.

En Power BI Desktop

Es el motor principal de ingesta. Se accede desde el menú inicio haciendo clic en el botón Transformar Datos. Se abrirá una ventana totalmente nueva que es el "Editor de Power Query".

El Motor In-Memory: VertiPaq

¿Cómo almacena los datos Power BI?

Power BI no es un visor de Excel. Utiliza el motor VertiPaq (xVelocity), una base de datos columnar en memoria. Almacena columnas en lugar de filas, comprimiendo drásticamente diccionarios de datos repetidos.

Regla de Oro: ¡Reduce las columnas, no te preocupes tanto por las filas!

El Poder del Query Folding

Query Folding (Plegado de Consultas): Es la capacidad de Power Query de traducir las transformaciones gráficas (Lenguaje M) en una única sentencia SQL (o lenguaje nativo) y enviarla de regreso al servidor de origen (ej. SQL Server) para que éste haga el trabajo pesado.

Romper el Folding

Si agregas un paso de Transformación no compatible (ej. un script de Python o una lógica IF muy compleja en M), el plegado se rompe. Desde ese paso en adelante, Power Query descargará todos los datos en crudo y forzará a la memoria RAM local de tu PC a procesar el ETL (Cuello de botella catastrófico).

Buenas Prácticas

Mantén los filtros (Filas filtradas), eliminaciones de columnas y agrupaciones (Group By) al INICIO de tu script de Power Query para garantizar que se deleguen a la base de datos origen.

Disección del Lenguaje M (Power Query)

M es un lenguaje funcional, fuertemente tipado y *Case-Sensitive* (distingue mayúsculas y minúsculas). Su estructura se basa en bloques let e in.

El Motor de Cálculo: DAX

Contextos de Evaluación (El Corazón de DAX)

A diferencia de Excel donde apuntas a una celda específica (A1), DAX opera sobre tablas y columnas enteras. DAX evalúa las fórmulas basándose en el entorno en el que se colocan. Este entorno se divide en dos:

Contexto de Fila (Row Context)

La capacidad de iterar. Sabe en qué fila exacta de la tabla se encuentra en este momento. Ocurre automáticamente al crear Columnas Calculadas o al usar funciones iteradoras (las que terminan en X, como SUMX).

Contexto de Filtro (Filter Context)

El conjunto de filtros aplicados por la interfaz de usuario. Cada etiqueta en un eje X, cada Slicer, cada clic en un gráfico, reduce la tabla en la memoria VertiPaq antes de calcular una Medida (Measure).

Iteradores vs Agregadores

// ERROR COMÚN (Agregador) Ventas_Error = SUM(Ventas[Cantidad] * Ventas[Precio]) // ESTO DA ERROR EN DAX
// SOLUCIÓN: ITERADOR (SUMX) Ventas_Correctas = SUMX( Ventas, // Tabla a iterar Ventas[Cantidad] * Ventas[Precio] // Expresión evaluada fila por fila )

SUM solo puede tomar una columna preexistente. SUMX inyecta un Contexto de Fila dinámico, recorriendo la tabla Ventas, multiplicando cantidad por precio, guardando el resultado temporal en memoria, y finalmente sumando todo.

El Misterio de CALCULATE

La función más compleja e importante de DAX.

1. Sobrescribir Filtros

Permite ignorar o modificar el Contexto de Filtro externo.
Ventas_Bogota = CALCULATE([Total_Ventas], Dim_Geografia[Ciudad] = "Bogotá")

2. Transición de Contexto

Cuando se invoca una [Medida] dentro de una Columna Calculada (que tiene un Contexto de Fila), CALCULATE (que se envuelve invisiblemente alrededor de toda Medida) transforma ese Contexto de Fila en un Contexto de Filtro equivalente. ¡Magia analítica!
